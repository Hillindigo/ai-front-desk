## 0. 总原则与施工约束

1. 全程在 `dev` 分支；每个任务开始前 `git branch --show-current` + `git status --short` 核对归属。
2. **TDD**：先写/跑直接相关测试再实现；阶段收尾跑全量测试、`compileall`、`git diff --check`。
3. 提交格式 `Phase I(类型)-标题≤15字`；一个提交一个独立大块，bug 单独提交；只提交当期白名单文件。
4. 破坏性操作（删除、匿名化、备份清理、密钥轮换）一律先 **dry-run + 隔离副本**，真实执行需明确授权。
5. 每个大块完成后，把实现走向/异常决策回写 `Phase-I-I0-基线与决策记录.md`；阶段收尾更新 `Phase-I-收尾与后续交接.md`。
6. 门禁不得跳过：I2 前必过 D9/D10/D11，I6 备份恢复前必过 D10/D11，I4 未过只承诺单实例。

验证命令基座（每个任务至少跑直接相关部分）：
```text
git branch --show-current
git status --short
python -m pytest -q tests/test_phase_i_<scope>.py
python -m pytest -q
python -m compileall agents api application config db services web evaluation app.py
git diff --check
```

## 2. I1 — 生产配置与安全加固（tests/test_phase_i_security.py）

**E1 安全配置校验/启动门禁**
- 开发/生产配置分离；生产缺会话密钥、允许来源、必要模型配置即拒启（用 D12 分级）。
- 禁默认管理员密码、硬编码令牌、调试异常页、敏感配置回显；提供密钥轮换与会话失效说明。
- 与现有 `initialize_system()` 降级启动并存：配置错误拒启，外部模型暂不可用降级/转人工。

**E2 安全中间件**
- CORS 收敛、TrustedHost/Host 校验、请求体大小、上传类型/大小、超时、基础速率限制。
- **SSE 单独超时策略**；CSP 先 report-only 盘点内联脚本/样式；补 `X-Content-Type-Options`/Referrer Policy/frame 限制。
- 限流按认证状态与端点分类（登录 vs turns 不同阈值），限流失败返回稳定错误码。

**E3 Cookie/会话加固**
- 固化 Cookie `HttpOnly`/`SameSite`/生产 `Secure`/生命周期；验证登录/退出/会话过期/撤销。
- 代理/HTTPS 边界：只信任明确代理来源，防伪造 scheme/host/client IP。

**E4 统一错误脱敏**
- 统一公开错误响应，防堆栈/数据库路径/模型密钥/内部 Prompt/隐藏推理泄漏。
- 认证失败、越权、跨门店、敏感管理动作、配置异常记脱敏安全事件（带 request_id）。

**E5 越权回归**
- 买家归属、商家 RBAC、active store、CSRF、跨门店对象访问全绿（横向回归 Phase G/H 既有能力，不重做身份模型）。

**验收**：默认/弱生产配置不能启动；未登录/越权/跨门店/CSRF 稳定拒绝；安全头、错误脱敏、会话撤销有自动化测试。

**提交建议（3 个）**：
- `Phase I(feat)-生产配置与启动门禁`（E1+E2）
- `Phase I(feat)-Cookie安全与错误脱敏`（E3+E4）
- `Phase I(test)-安全加固回归测试`（E5）

## 3. I2 — PII 治理、导出、删除与保留（tests/test_phase_i_privacy.py）

**E6 脱敏与最小展示**
- 按 D14 数据字典对日志/异常/审计详情/管理页面做字段级最小化与脱敏；禁记录密码、会话令牌、完整认证头。
- 日志不记录 Prompt 全文、模型密钥、高基数完整 PII。

**E7 商家侧客户导出**
- 服务 + API：受 RBAC/store scope/CSRF 保护，参数含范围、生成者、时间、格式、审计事件。
- 按 D11：专用目录+服务端文件名+最小权限、短时一次性下载令牌、明确 schema（禁整库 dump）、下载/过期清理 + 脱敏审计。
- 测试：跨门店导出拒绝、路径穿越、过期文件访问失败。

**E8 删除/匿名化应用服务**
- 按 D14 逐实体策略（会话、消息、摘要、偏好、墓碑、预约、回访、审计、UserBehavior、旧 UserPreference、UserRecommendation、知识索引等）。
- 已完成预约等法定/业务审计事实不硬删：去标识化 + 说明原因。
- 删除流程：预览/dry-run、幂等键、事务边界、失败恢复、结果清单；禁止只从页面隐藏。
- 删除后 ContextBuilder、搜索、客户后台、会话恢复、模型输入不再注入（墓碑/失效/屏蔽机制）。
- 按 D10 写删除登记/抑制记录；补“从删除前备份恢复后 PII 不可查询/不可注入”测试。

**E9 保留与清理**
- 在线/日志/临时导出/上传/备份各自保留期限（D6 定值）；清理任务默认 dry-run + 审计。
- 清理含备份过期销毁（D11 加密文件）。

**验收**：跨门店不能导出/删除；重复删除不产生不一致；删除后所有规定入口不可恢复被删除 PII；保留的业务/审计事实已匿名化且理由可追踪；恢复后防 PII 复活通过。

**提交建议（4 个）**：
- `Phase I(feat)-日志与界面PII脱敏`（E6）
- `Phase I(feat)-商家侧客户导出`（E7）
- `Phase I(feat)-客户删除与匿名化`（E8）
- `Phase I(feat)-数据保留与清理`（E9）

## 4. I3 — 运行观测、审计与成本延迟指标（tests/test_phase_i_observability.py）

**E10 关联与运行记录**
- 按 D13 接线 request_id 贯穿；Agent 运行记录（工作流/模型/提供方/语料版本/开始结束/状态/错误类别/token/估算成本）。
- 成本记录含计价版本与币种（D7）。

**E11 埋点**
- turns/知识检索/模型调用/预约命令/人工接管/后台任务 阶段耗时 + 稳定失败类别；区分用户错误/领域冲突/模型失败/检索不足/依赖失败/系统异常。

**E12 健康/就绪端点**
- `/health/live`（进程）与 `/health/ready`（可承接）分离（D12）。
- ready 检查 DB、迁移版本、知识索引版本、后台任务状态；就绪失败不得返回伪健康。

**E13 门店指标查询/报表**
- 最小门店范围运营/质量指标查询或离线报表；验证权限、标签基数、数据脱敏（指标标签禁 PII）。

**E14 阈值与不静默**
- 本地阈值/告警规则文档：失败率、P95、旧索引、连续模型失败、备份过期；无外部告警平台不伪造通知。
- 观测写入失败有 drop/error 计数，查询区分“无事件”vs“观测记录丢失”；关键审计尽量与业务事实同事务。

**验收**：一次跨角色验收可从请求关联到 Agent 轮次、知识证据、预约结果、审计事件；指标不泄漏 Prompt 全文/令牌/完整 PII。

**提交建议（3 个）**：

## 5. I4 — 知识索引一致性与安全降级（tests/test_phase_i_knowledge_consistency.py）

**I4-A（默认，单实例）**
- 启动门禁强制 worker=1；`/health` 暴露本地索引版本与数据库知识版本、最后刷新时间、失败状态。
- 部署文档/README 只承诺单实例一致性（不宣称多进程安全）。

**I4-B（可选，仅当明确选多进程）**
- 持久化 `knowledge_version` 为事实源；版本检测 + 本进程原子重建；刷新失败保留旧快照并标记 `stale/degraded`；高风险知识拒绝确定性回答转人工。
- 两进程/两容器发布-检测-刷新-查询 + 并发/失败注入测试。

> I0 D1/D2 默认单实例，「不引入分布式基础设施」。若选择 I4-B 需先更新 I0 决策并说明原因。

**验收**：I4-A 单实例下本地索引与持久版本一致、health 暴露版本、文档不宣称多进程安全；I4-B 版本收敛、失败可观测、旧快照不损坏、高风险旧知识不被当作当前事实。

**提交建议**：`Phase I(feat)-知识版本健康与单实例门禁`（I4-A）；I4-B 仅当决策后追加提交。

## 6. I5 — 模型/RAG/摘要/工作流质量评测（tests/test_phase_i_evaluation.py）

**E18 人工量表与版本记录**

## 7. I6 — 并发、故障恢复、备份与清理演练（tests/test_phase_i_reliability.py）

**E20 并发场景**
- 同会话重复轮次、同时段竞争预约、接管与 AI 同时请求、重复人工回复、并发知识发布。
- 验证 `client_request_id`、预约 `idempotency_key`、控制状态、数据库事务职责；无重复消息/预约/状态跃迁。

**E21 故障注入**
- 模型超时/空流、Embedding 失败、数据库锁竞争、发布失败、进程中断、SSE 断线；失败路径可重试/转人工。

**E22 重启恢复**
- 重启后会话、摘要、工作流、预约、人工接管、知识版本、后台任务状态一致。

**E23 一致性备份**
- SQLite 一致性备份（不复制正在写入的库）+ 必要上传/知识源 + 版本清单（schema/知识版本/时间）。
- 按 D11 静态加密 + 密钥分离 + 校验和；备份不写入 Git；保留/清理 dry-run。
- 备份按敏感数据处理。

**E24 隔离恢复演练**
- 隔离临时目录：初始化→写验收数据→备份→破坏/替换→恢复→迁移→核心验收查询。
- 含 D10 场景：删除客户→备份→恢复→重放删除登记→验证 PII 不复活。
- 记录实测 RPO/RTO 与单实例限制，不作商业级承诺。

**验收**：故障与恢复后关键实体数量/状态/关联 ID/知识版本一致；重复请求不产生重复业务；备份实际可恢复而非只证明文件存在。

**提交建议（4 个）**：
- `Phase I(test)-并发与幂等场景`（E20）
- `Phase I(test)-故障注入与降级`（E21）
- `Phase I(feat)-备份恢复与清理脚本`（E22+E23）
