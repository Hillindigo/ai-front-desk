# Phase I I4：知识一致性部署限制（I0 D1/D2，单实例）

> 日期：2026-08-18
> 决策来源：`Phase-I-I0-基线与决策记录.md` §5 D1/D2

## 1. 支持的运行拓扑

**默认支持且唯一被验证的拓扑：单实例 FastAPI 进程 + SQLite + 进程内 FAISS 索引。**

- `/health/live` / `/health/ready` 暴露数据库知识版本与本地索引版本（`local_index_version`）。
- 单实例下进程内索引与持久 `knowledge_version` 应保持一致；
  若 `/health/ready` 显示 `knowledge_stale=true`（本地 `index-N` 与 DB 版本不一致），
  表示索引未收敛到最新发布，应触发重建/刷新或拒绝以其作答。

## 2. 部署限制（明确不做）

- **不宣称多进程/多实例知识一致性**：`worker > 1` 或多进程部署时，各进程的
  进程内 FAISS 索引可能彼此陈旧且无同步机制，**不得用于生产**。
- 部署模板 / 启动命令必须强制 `worker=1`（Uvicorn 单 worker）。
- 若未来需要有限多进程一致性（版本检测 + 原子刷新 + stale/degraded 降级），
  属 I4-B，需先更新 I0 决策并单独实现与验收。

## 3. 验收口径

- 单实例下：`/health/ready` 正常返回 200，`knowledge_version` 与
  `local_index_version` 可读取且可对比；`knowledge_stale` 为 bool 或 null。
- 文档、README、部署说明不得出现"多进程安全"措辞，除非 I4-B 已通过。
