# Phase I I3：指标字典与阈值告警（D7/D13/E14）

> 日期：2026-08-18
> 关联：`GET /api/v1/admin/metrics`（既有审计指标 + run_metrics）、`/health/live`、`/health/ready`。

## 1. 指标字典（测量口径）

| 指标 | 来源 | 定义 / 测量口径 | 备注 |
|---|---|---|---|
| 请求成功率 | run_metrics.outcomes | completed / total（进程内，含 SSE 轮次） | Fake 模式不混入真实模型口径 |
| P95 延迟 | run_metrics avg/max | 进程内 run 起止毫秒；样本窗口=进程会话；小样本不计算 P95（标记低置信度） | 冷/热启动分开解释 |
| 模型失败率 | run_metrics.error_categories | 按失败类别计数（model_timeout/exception/…） | 类别需稳定归类，不用自由文本 |
| 知识拒答率 | 待 I5 评测 / run 失败类别扩展 | 检索无依据拒答占比例 | 由知识评测集给出 |
| 单轮 token/成本 | 待 I5 评测 | 记录 token 数与计价版本 | 成本需含计价版本与币种 |
| 索引版本落后 | /health/ready.checks.knowledge_version | 本地 vs 持久知识版本差异 | 落后过长即降级/告警 |
| 备份过期天数 | 备份清单时间戳 | 最近成功备份距今 | 见 I6 |
| 观测丢失 | run_metrics.drop_count | 超过缓冲上限或被丢弃的 run 数 | 用于发现"观测缺席≠无事件" |

## 2. 阈值 / 告警规则（本地，无外部告警平台不伪造通知）

| 阈值 | 触发 | 处置 |
|---|---|---|
| 模型失败率 | 连续 ≥5 轮同会话失败，或 5 分钟窗口内失败率 >30% | 该会话明确转人工；不静默用旧知识 |
| run 丢失 | drop_count 持续增长 | 扩大缓冲上限；检查埋点异常 |
| 健康检查 | /health/ready 返回 503 | 停止承接流量，DB/迁移排障 |
| 索引陈旧 | 知识版本落后超过约定窗口 | 触发刷新；高风险知识拒绝确定性回答 |
| 备份过期 | 超过 RPO 窗口无成功备份 | 告警并补备份（I6） |

**约束（E14）**：观测写入失败必须有 drop/error 计数，查询结果区分"无事件发生"与"观测记录丢失"；关键业务审计与业务事实尽量同事务，不因观测失败回滚业务。

## 3. 关联 ID 边界（D13）

- `request_id`：服务端生成（本次以 client_request_id 复用为 run 关联，见下节说明）。
- `client_request_id`：客户端幂等/重试键，有长度字符校验；**不替代服务端关联 ID**。
- `run_id`：服务端 Agent 执行实例；replay 引用 `original_run_id`。
- `idempotency_key`：仅业务命令（预约）使用。

> 当前实现把 `client_request_id` 直接既作轮次去重又作 run 记录关联（replay 覆盖）。
> 阶段内宜保持此兼容口径并在交接中标注；未来区分"客户端键 vs 服务端 request_id"作为后续待办。

## 4. 当前实现范围

- ✅ 健康/就绪端点：`/health/live`、`/health/ready`（DB、迁移、知识版本）。
- ✅ 进程内 RunRecorder：turns 端点包裹埋点，记录耗时/结果/失败类别；`/metrics` 暴露 run_metrics。
- ✅ 观测不静默：RunRecorder 有 drop 计数。
- ⏳ 模型 token/成本埋点：待 I5 评测铺垫；单轮成本手工记录。
- ⏳ 请求级服务端 request_id 贯穿：当前以 client_request_id 关联，服务端独立 ID 列为待办。
